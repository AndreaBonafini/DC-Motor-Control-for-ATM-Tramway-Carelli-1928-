## 1. Project Goal

This project focuses on modeling, parameter identification, and control design for a **separately excited DC motor** used to propel an ATM tramway vehicle ("Carelli 1928"). The objective is to design a control system capable of making the tramway follow a specified speed profile over a 10 km track with varying slopes, while respecting acceleration requirements and motor constraints.

---

## 2. System Modeling

* **Mechanical Model:** The tramway is modeled as a single wheel with radius R and equivalent mass M on an inclined plane. Rolling without slipping is assumed. The equation of motion considers the motor torque (T), traction force ($F_t$), friction force ($\beta v$), gravitational force due to slope ($\gamma$), and inertia ($M \dot{v}$). The key relationship $T = F_t R$ is derived. The transfer function from Torque to angular speed ($\omega$) is $F_{\omega T}(s) = \frac{1/(R^2 \beta)}{1 + (M/\beta)s}$.
* **Electrical Model:** A standard separately excited DC motor model is used, relating armature voltage ($v_a$), current ($i_a$), resistance ($R_a$), inductance ($L_a$), back-EMF (E), excitation voltage ($v_e$), current ($i_e$), resistance ($R_e$), inductance ($L_e$), and motor speed ($\omega$). Linearity of the magnetic circuit ($\Psi_{ae} = K_{ae} i_e$) is assumed. The relevant transfer functions for armature current ($F_{I_a V_a}(s) = \frac{1/R_a}{1 + (L_a/R_a)s}$) and excitation current ($F_{I_e V_e}(s) = \frac{1/R_e}{1 + (L_e/R_e)s}$) are derived.
* **Parameter Identification:** Motor and mechanical parameters ($R_a, L_a, R_e, L_e, K, \beta, R, T_n$, etc.) were calculated based on the provided specifications (nominal voltage, efficiency, time constants, mass, acceleration requirements, friction characteristics).

---

## 3. Control Strategy

A **cascaded control structure** is implemented using PI controllers, assuming sensors and power supplies are ideal:

1.  **Outer Velocity Loop:** Controls the mechanical speed ($\omega$) to follow the reference profile ($\omega_{ref}$). A PI controller is designed with a cutoff frequency ($\omega_{c_{ome}}$) chosen to meet the acceleration requirement, intentionally allowing saturation. Feedforward compensation is added for the gravitational disturbance (slope) and back-EMF.
2.  **Inner Armature Current Loop:** Controls the armature current ($i_a$) based on the torque reference generated by the velocity loop. Designed to be significantly faster than the velocity loop. A PI controller is tuned based on the armature circuit dynamics. Output is saturated at $V_{a_n}$.
3.  **Excitation Current Loop:** Controls the excitation current ($i_e$) to achieve field weakening for speeds above the base speed ($\omega_n$). The reference $I_{e_{ref}}$ is set to $I_{e_n}$ below $\omega_n$ and calculated to maintain $V_a \approx V_{a_n}$ above $\omega_n$. A PI controller is tuned based on the excitation circuit dynamics.

**Anti-windup (clamping)** is implemented for all PI controllers to handle saturation. A switch logic ensures the armature circuit activates only after the excitation circuit reaches steady state.

---

## 4. Key Results

* The designed cascaded PI control system successfully tracks the complex speed reference profile over the 10 km track, including segments with positive and negative slopes.
* The system meets the acceleration requirement, reaching $60 \, km/h$ from rest within 25 seconds.
* Field weakening operation is correctly implemented, reducing the excitation current when the speed reference exceeds the base speed to allow higher speeds while respecting voltage limits.
* Armature current and motor torque constraints are respected throughout the simulation.
* Feedforward compensation effectively mitigates disturbances due to slopes, although some transient speed drops occur without it.

## 6. How to Run

1.  Open MATLAB.
2.  Run the `Parameters_estimation.m` script. This calculates all necessary parameters and saves them into `.mat` files (`Radius.mat`, `psi_ref_parameters.mat`). Ensure `my_parameters.mat` is also present or generated if needed.
3.  Open the `DC_control.slx` Simulink model.
4.  Run the simulation (Simulation time is set to 700 seconds in the model configuration).
5.  Observe the results in the Scopes within the model or analyze the saved workspace variables (if configured in `Simulink.DataIOCC`).
